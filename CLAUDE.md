# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`s1ops` is an offline-first, vendor-neutral LLMOps SDK + CLI for **System 1 decision models**: backends that return a calibrated probability distribution rather than text, in one of three primitives — `noul` (binary `p`), `choice` (K options), `score` (ordinal 0..L-1). It covers question linting, post-hoc calibration, threshold/escalation-band compilation, slice and blind label audits, shadow/judge comparison, drift monitoring, a runtime `DecisionGate`, `safe-v1` exporters (Langfuse, Phoenix/OpenInference), and a local FastAPI web workbench.

Design docs (in `docs/`, written in Korean; README is English):
- `docs/ARCHITECTURE_AND_PLAN.md` — data contracts, module map, Phase 1–3 (all done).
- `docs/NEXT_STEPS_PLAN.md` — Phase 4 open work: CI, live HTTP backends, `DecisionGate` choice/score, TS SDK.
- `docs/REVIEW_AND_COMPARISON.md` — why existing System 2 tools don't fit, failure modes the guardrails encode, naming decision.

## Commands

```bash
uv sync --all-extras                          # install (extras: langfuse, typesafe)
uv run pytest                                 # full suite, fully offline, no API keys
uv run pytest tests/test_drift_runner_and_gate.py::test_runtime_decision_gate_and_cli_web
uv run s1 demo examples/data                  # seeded demo workspace (new or empty dir only)
uv run s1 web --workspace examples/data --host 127.0.0.1 --port 8765
```

The full end-to-end CLI pipeline over the demo workspace (lint → fit → apply → audit → policy tune → slice → labelaudit → compare/judge → drift → probe/gate → export) is spelled out in README's Quickstart §3; later steps consume `fits.json`/`policy.json` produced by earlier ones.

No linter or type checker is configured in `pyproject.toml`. CI (`.github/workflows/ci.yml`) runs the locked suite on Python 3.11–3.13 and `scripts/release_check.py` on the built wheel and sdist; `release.yml` publishes by manual dispatch on a `vX.Y.Z` tag (procedure in `docs/NEXT_STEPS_PLAN.md` Track 1). The repository is private while the package is public, so package metadata must not name it.

## Architecture

**Package layout.** `src/s1ops/` is the real package; `src/s1/__init__.py` is only a star-re-export alias so `import s1` works. `s1ops/__init__.py` resolves its exports lazily (PEP 562 `_LAZY`, with the real imports under `TYPE_CHECKING`), and `improve/calibrate.py` imports `scipy.optimize` / `sklearn` inside `_fit_params`, so loading and evaluating a noul gate keeps the fitting stack, the CLI and the web app unloaded (`tests/test_light_gate.py`, for decision-plane's per-call hook). A new export goes into both `_LAZY` and the `TYPE_CHECKING` block. Both `s1` and `s1ops` console scripts point at `s1ops.cli:console_main`, which wraps `main` (a library call: decision-plane's evals use it, so it prints but never flushes, closes or replaces the process's stdout), in a single argparse file with every subcommand. The demo generator lives in the package (`s1ops/demo.py`, behind `s1 demo`) so it works from `pip install`; tests build their fixture workspace into `tmp_path` with `from s1ops.demo import generate_workspace` rather than using checked-in data. Its `fitted_at`/`created_at` fields are wall-clock, so compare workspaces with those dropped. `pytest` runs with `pythonpath = ["src", "."]` so `tests/test_release_check.py` can import `scripts.release_check`. `examples/data/` is gitignored output.

**Data flow.** `contracts/` defines everything else's inputs: `questions.py` (Noul/Choice/Score models, `question_id`, `/v1/decisions` conversion), `records.py` (strict `jev-record/1` / `s1-record/1` parser and grouping), `schemas.py` (`PolicyEntry`, `s1-policy/1`). `improve/calibrate.py` writes `fits.json`; `improve/policy.py` writes `policy.json`; `improve/trainset.py` writes `s1-training-manifest/1`, what an external trainer trains a named checkpoint on (s1ops starts no training), and `improve/trainrun.py` writes `s1-trainrun/1`, the record of a finished run, refusing a data file whose `(dataset, item_id)` set differs from the manifest's (exit 2 for an unlisted item); `trainrun._check_doc` is the one rule for a record's contents, run by `build_trainrun` before the id is hashed and by `load_trainrun`, so the writer never writes what the reader refuses, and an extra key such as `state` is refused, as is a trainer setting or summary metric named `state` (`_check_scalars`; exact name only, `max_state` is a setting). `--training-run` (`compare`, `policy tune` / `curve`, `export langfuse`) shows which record's run produced a model, matched by `model_served` equal to the record's `checkpoint`: `trainrun.runs_by_checkpoint` is the one rule for the records taken (each re-checked as a file is, since the export attaches `doc`; a checkpoint that answered no input record, or two runs for one checkpoint, is exit 1), a printed row gains `trainrun_id` (`compare`: `primary_trainrun_id` / `shadow_trainrun_id`), and the Langfuse export gains `training_runs` and `metadata.trainrun_id`. Without the option every output is byte for byte what it was. `policy tune` also writes `PolicyEntry.trainrun_id` (provenance like `source_sha256`: outside `policy_sha256`, nothing routes on it), and `to_dict` leaves the key out when it is null, because `_PolicyRow` forbids extra keys and a reader at 0.11.1 or earlier, decision-plane's pinned commit among them, refuses a file that has it; `build_langfuse_events` refuses (`TrainRunError`) a record of another run than the one a policy for that model names; `runtime/gate.py` (`DecisionGate`) loads both at runtime. `s1 promote` (`cli._cmd_promote`) is README's promotion check as one command over records already probed: each step is the real subcommand, its arguments parsed by `build_parser()` from a skeleton and then set (`_promote_step`), calling the function that returns what the command prints (`_compare`, `_drift`, `_fit`, `_apply`, `_policy`; each `_cmd_*` only prints it), so a step cannot differ from the command run by hand (`tests/test_promote.py` compares the two). A refusal keeps its exit code and gains `promote: <step>: ` (`cli._failure` is the one map from an exception to its line and code, used by `main` too). `compare` and `drift` run before the first write. `monitor/runner.py` defines the `Backend` protocol and `DeterministicMockBackend`, and runs probes under `ledger/journal.py`; `run_batch` and a live `s1 probe` take no default model, since `model_served` is whatever the server reports and an echoing server reports what was sent, and an empty or non-string name is refused before anything is sent (`read_records` would refuse the records); `monitor/backends.py` has `HttpSystemOneBackend` (wraps `typesafe-sdk`, the `typesafe` extra) and `OpenAIDecisionsBackend` (wraps `openai`, the `openai` extra), both imported lazily; their SDK and transport logs (`QUIET_LOGGERS`) are dropped during `infer`, and a new logger that speaks during a request fails `tests/test_openai_backend.py`. `web/app.py` serves `web/static/index.html` and computes tab data from a workspace directory.

**Invariants that cut across modules** — preserve them when changing anything:
- **Group key is `(question_id, model_served, primitive)`.** Metrics, fits, policies, slice reports and exports are never pooled across groups (`s1 slice` and `/api/slices` report `{"groups": [...]}` through `slices.slice_inputs_by_group`, after `select` has checked the whole file). Drift's report is per `question_id` and pools that question's models, so a model change shows; its policy lookup and `--calibrated` fit check use the full group key, and it refuses (`DriftInputError`) a question whose records, on either side, name more than one primitive. `compare_records` refuses (`CompareInputError`) a question whose paired rows on one side span more than one `model_served` or `primitive`. Changing a question's wording or option order changes its `question_id`.
- **`question_id`** = `q-` + first 16 hex of SHA-256 over the normalized `/v1/systemone` wire JSON (option order preserved).
- **`safe-v1` zero-state:** raw item `state` text is never written to records, ledgers, probe output, or exports — only `(dataset, item_id)` and `state_sha256`. The parser refuses a `state_sha256` that is present, not null and not 64 lowercase hex characters (`records._state_sha256_problem`, in `_parse_record` before the no-answer return, so `reparse` and a decoded row are covered): both exporters copy the field out, and its message gives the value's type and length, never the value. `s1 apply` copies input rows, so every path it writes through (`records.without_state`, also in `apply_to_record`) leaves a top-level `state` out and reports `state_dropped`. `Ledger.reserve` / `settle` refuse a `state` metadata key (`ValueError`, before anything is written), and `ledger.recover` refuses a journal whose complete events carry one rather than copy it into a new file; a journal written with one before the refusal still opens. `run_batch` copies only `ANSWER_KEYS` from a backend's `answer`, so a custom backend cannot set `state`, an identity field or a `label`. `s1 labelaudit patch` copies rows too, through `without_state` (`labelaudit.patch_labels`: a finished sheet's answers become the labels of the records the sheet was built from, a failed probe's row included, whose label the parser does not read (`raw["label"]`, checked with `label_problem`); the sheet must name the key's question (`sheet_question_id`) and answer no item the key lacks, refusing (`LabelPatchError`, with `.source` naming the key, sheet or records; `RecordError` by line for a row whose label the review was not of) rather than overwriting anything else). A local `states_local.jsonl` (`--states`) is read by two commands only: `s1 probe` sends each state to the backend, and `s1 labelaudit sheet` writes the state text of every reviewed item (top flags plus random controls) into the review sheet, which is meant for a human reviewer.
- **Record validation** rejects NaN/Inf (on a line of a file, `_read_line` refuses `NaN`, `Infinity` and a float literal that overflows, such as `1e400`, anywhere in the row, so no writer copies one from an unvalidated field; an integer past the float range is refused in a validated field, by `_number`, and elsewhere only past Python's digit limit, by the decoder; a decoded row through `parse_record` has only validated fields checked), a lone surrogate (U+D800..U+DFFF: on a line of a file, an escaped one in any key or value of the row, found by `_row_surrogate_problem` behind a two-substring gate, since `save_fits` / `save_policies` and both exporters fail part-way on one; in a decoded row, in the strings `_string` validates; `records.surrogate_problem` is the one rule and names the code point, never showing it), JSON bools posing as numbers, probability sums outside `1 ± 0.02`, and score keys that are not 1–20 ASCII digits naming distinct levels in `0..2**53`, raising `RecordError` with a 1-based line number; `read_records` also puts the file's path first in the message (`.path`), refuses a line that is not UTF-8 by its number (read with `errors="surrogateescape"`, so universal newlines stay), and a path-based `audit_drift` reads with `use_calib=True` so a bad stored `calib` names its file too. Errors found after reading name it as well: `read_records` sets `Record.path` (keyword-only, outside equality and `repr`), `select`'s duplicate-item and class-mismatch errors start with it and say where the first occurrence is (`first on line N of <path>` when it is another file), and every re-parse of `Record.raw` (drift, routing, both exporters) goes through `records.reparse`, never `parse_record(r.raw, ...)`, so its `RecordError` keeps the path. `records.score_level` / `score_levels` is the one score-key rule; the gate, `compare_records` and the exporters call it too. `records.label_problem` is the one label rule: the parser applies it to a record, and `check_labels` (`monitor/runner.py`, after `check_states`, in `run_batch` and `s1 probe`) to a states row against every question in `LABELED_ROLES`, before anything is sent. The strings a probe copies from its inputs into records are refused with a lone surrogate before anything is reserved, each where it was already checked: `check_states` (`item_id`, `dataset`, `split`), the model name (`run_batch`, and `_probe_backend` for `--model`), a question's name (`probe_tasks`), which also computes every task's `question_id` so a wording it cannot hash stops the run before an earlier question is paid for; a new copied string needs its own (`test_every_string_a_probe_record_holds_has_a_check_before_or_after_the_call`).
- **Out-of-sample enforcement:** `fits.json` records every `[dataset, item_id]` used in fitting plus `source_sha256`, hashed from the one read of the records (`records.read_records_hashed`), since a FIFO input has only one. `s1 apply` exits **2** on an in-sample item (unless `--allow-in-sample`) and **3** on a `model_served` mismatch (unless `--pass-through-unfitted`, which writes every record the fit file has no fit for unchanged, except `state`, and prints a summary; class mismatches and in-sample items are still refused); `DecisionGate` raises `ModelServedMismatchError`. `improve/calibrate.py::apply_fits` is the one apply path: `s1 apply` writes its `lines`, and `s1 drift --fit` / `s1 export --fit` read its `records` (those lines through `records.read_row`, so a report equals the one over the written file; key order decides a tied Choice's `predicted`). It re-parses each input raw, so the caller's parse mode does not matter, and raises `FitApplyError` (`.kind` from the fit lookup, mapped to exit 2 / 3 / 1 in `main`).
- **Training leakage:** `--training-manifest` on `fit`, `audit`, `policy tune` / `curve` and `compare` exits **2** (`TrainedItemError`) when a selected group served under the manifest's `checkpoint` holds an item it trained on, inherited ones included (`trainset.check_not_trained`; `compare` checks shared pairs, each against its own side's model). An item is `(dataset, item_id)` across questions, since rewording changes `question_id`. A manifest whose checkpoint answered no record in the whole input file is exit 1 (`load_trained`), which catches a misspelled name and promises nothing about the selected rows. `apply` takes no manifest, by owner decision: a fit rule over-refused `--pass-through-unfitted` and still missed a `calib` carried through it, so a stored `calib` is not looked behind. A manifest holds ids, question ids and labels only, no `state` or wording. `s1 probe` copies a states row's `split` into its records, as it does `label`.
- **`policy_sha256`** fingerprints each `PolicyEntry`'s routing fields. Checking it is opt-in: `evaluate_*(expected_policy_sha256=...)` / `s1 gate --expected-sha256` raise `PolicyIntegrityError` on mismatch. `load_policies` also compares a stored non-null `policy_sha256` with the recomputed one and raises `PolicyFingerprintError` (a `ValueError` in `contracts/schemas.py`, so it never imports the gate) on mismatch; an absent or null one is only recomputed, which is how a hand edit is accepted.
- **Fit provenance:** `Fit.fit_sha256` hashes the fields that decide the map (group key, method, classes, params; not `fitted_at`, `items` or `n`). `s1 apply` writes it into each `calib`; `s1 policy tune --use-calib` refuses a selected record without the calibrated distribution and records the one `fit_sha256` its group shares (records from before it: null; mixed: exit 1; every CLI refusal goes through `cli._tuned_fit_sha256`, which starts it with the records path), and `s1 policy curve --use-calib`, `s1 slice --use-calib` / `/api/slices?use_calib=true` (exit 1 / 400 naming the records file; raw by default, read with `use_calib=True` so malformed probabilities in a stored `calib` object are refused in both modes, while a `calib` that is not an object and its `fit_sha256` are checked only under `--use-calib`, predicting through `slice_inputs_by_group(raw=True)`) and the web simulator under `use_calib` (400; unset is auto: calibrated when any tuned record of the chosen group has `calib`, so a mixed group is still refused, raw when none does; the response names `distribution`) run the same check (`improve/policy.py::tuned_fit_sha256`, `CalibInputError`) on the groups they select; the gate raises `PolicyIntegrityError` when a calibrated policy's non-null `fit_sha256` differs from its fit's, and reports (`routing.policy_distribution`: drift, both exporters) raise `RoutingInputError` for a record whose `calib.fit_sha256` differs, is null or missing, or is not a string (`in_fit_sample` exempts nothing). That error starts with the record's file (`RoutingInputError.path`, from `Record.path`), except under drift, which names the side (`reference records:` / `current records:`) and keeps the path on the error. A null policy takes any fit or `calib`. It is part of `policy_sha256`, and it hashes fitted parameters bit for bit, so tests compare it within one run, never as a literal from one platform.
- **One policy and one fit per group:** `load_policies`, `load_fits` and `DecisionGate(...)` refuse a repeated group key. A policy's band is checked on load: `escalation_band` needs `0 <= band_lo <= band_hi <= 1`, `error_budget` has no band bounds.
- **`policy.json` / `fits.json` loading** validates through strict pydantic row models (`_PolicyRow` in `contracts/schemas.py`, `_FitRow` in `improve/calibrate.py`) and then builds the frozen dataclasses. A malformed file raises `ValueError` / `FitError` naming the file and the field path (`policies.0.threshold`); never let a `TypeError`/`AttributeError` escape a loader.
- **Thresholds are tie-safe:** System 1 APIs return rounded probabilities, so `select_threshold` accepts/rejects whole equal-probability groups atomically.
- **Drift's PSI alerts are tested:** PSI (rounded to 6 decimals, as reported) over 0.25 / 0.10 raises CRITICAL / WARN only with a permutation p under 0.01 / 0.05 (strict). `psi_test` draws the reference side's bin counts from a multivariate hypergeometric over the pooled counts (O(bins) per resample, the same distribution as a random split), 1,000 resamples, one generator per question seeded from `PSI_SEED` and the `question_id`, so another question never changes a p; the observed PSI and every resample go through `_psi_from_counts` at full precision. A non-significant PSI over a threshold goes to `notes`, never `alerts` (the web badges every alert with the status). `psi_resamples` is 0 (threshold-only rule) or >= 1000. Tests never pin a p literal (numpy streams are not promised stable across versions).
- **Ledger is reserve-then-settle** with exclusive `flock` on `<journal>.lock`, rejects hard-linked ledgers, and halts with `LedgerUnusable` if a measured cost exceeds its reservation (`settle` only records the overrun; `run_batch` raises right after it). `run_batch` reserves per attempt and settles `measured` when a cost is reported, `unsent` only when the request provably never left, `unknown` otherwise — never `unsent` for a request that may have been billed. Before settling it reads each answered record back over its dumped text (`_readable`; `Ledger.settle` itself refuses a `model_served` JSON cannot hold, and only the text shows a `NaN` in a field the parser does not read); an unreadable one becomes `BackendError("invalid_response", sent=True, usage_usd=resp.cost_usd)`, so the failure path settles and records it (a `cost_usd` `Ledger.settle` refuses raises there instead, with no record and the reservation left open, as it does for a readable response), and a failure record whose `error_code` would not read back says `invalid_response`. `BackendError` messages carry an error code only, never server text (a server may echo `state`).
- **Lint rules** `JL000`–`JL060` (a range with gaps, not 61 rules) can be suppressed via `x-s1-lint` / `x-jev-lint` keys, except `UNSUPPRESSIBLE` (`JL000`, `JL001`, `JL003`, `JL020`). A question carries one of the two keys, not both. `lint.loader.read_question_entries` is the one reader of a questions file (`lint check`, `probe`, `labelaudit sheet --questions`): names to questions, or `{"questions": {...}}` when that is the only key and its value's `type` is not a string; a repeated name, an empty file or nesting past `MAX_NESTING` is an error there, so no later recursion can overflow. Each entry goes through `lint.loader.parse_question` (`monitor/runner.py::probe_tasks` too; only a question model skips it), so the extension is stripped before `question_id` and its `inverse` is the inverse probe's wording; without one the inverse is generated (`"Is it false that: ..."`, true/false criteria swapped). Inverse records carry `probe_inverse` (`supplied` / `generated`); `audit_probe` reports `inverse_source` and refuses a question and model whose records of one role span more than one `question_id`.

**CLI error contract** (`cli.py`, tested in `tests/test_cli_errors.py`). Exit codes (`s1 promote` passes on its steps'): 0 ok, 1 any user-facing failure (including argparse usage errors, via `_Parser`, which print that one line and a `-h` pointer, no usage block), 2 in-sample refusal (`apply`, `drift --fit`, `export --fit`, `--training-manifest` on a checkpoint's trained items, `trainset record` on a data item its manifest does not list), 3 `model_served` mismatch (`apply` without `--pass-through-unfitted`, `gate`), 4 `drift --fail-on-critical`. Commands raise `CliError(message, code)` and `main()` prints one `s1: <message>` line; `_fail` and `_Parser.error` escape every non-printable character (`_one_line`: `\n`, `\x1b`, `\u202e`; printable non-ASCII and backslashes kept), so the line holds whatever ids or paths a message interpolates (reports such as `lint check`'s text format and uvicorn's logs are not error lines); it also maps `OSError`, `ValueError` (covers `RecordError`/`FitError`/`LedgerCorrupt`/`JSONDecodeError`), `PolicyIntegrityError`, `BudgetExceeded`, and `ModelServedMismatchError`. `KeyError` is deliberately not mapped — convert it at the call site. `console_main()` flushes stdout before exiting: a reader that left early (`| head`) keeps the command's own exit code, never 120, and another write failure on a command that had succeeded is one more `s1:` line and exit 1; a pipe that breaks mid-print is exit 1, since the command never reached its own code. `S1_DEBUG=1` re-raises library exceptions for a traceback; `CliError` always prints one line. When a backend's `close()` raises an `Exception`, `s1 probe` keeps its own result: an error that ended the command stays that error, and a finished run prints no summary and exits 1 with one line naming the exception's type, never its text, and the records kept and failed (`S1_DEBUG=1` re-raises it). An interrupt during `close()` propagates. Input paths are pre-checked by dest name via `_INPUTS`, which also names the producing command (`run \`s1 fit\` first`); the check (`_require_file`) uses `os.stat`, so a symlink loop or an unsearchable parent is "cannot be read" and a dangling link is named as one rather than "not found", and it accepts a FIFO (`s1 audit <(cat f)` is supported); a new input argument needs an `_INPUTS` entry, and an output path must not reuse an input dest name. `lint check` is exempt: it reports an unreadable file as a `JL000` finding inside its own report. Every argument needs `help=` (a test enforces it), and each `add_parser` must pass `**_FMT`, since argparse does not inherit `formatter_class`.

**Web workbench errors** (`tests/test_web_errors.py`, `tests/test_input_errors_name_file.py`). Each file read goes through `_load_or_400`, which catches `ValueError` (malformed content) and `OSError` (a file that exists but cannot be read: a directory, no permission), so either is HTTP 400 naming that file, once (a loader message that already starts with the path is not prefixed again). Presence is `_present` (`os.lstat` then `os.stat`), never `Path.exists()`, which is `False` for a loop or a dangling link and, for a permission error, raises on Python 3.11-3.13 and is `False` on 3.14: nothing at the path is absent (optional, 200), while a path that cannot be inspected (no search permission on a parent, a symlink loop), a dangling link, or a FIFO or other non-regular file is a 400 naming it (a FIFO would block the request); `_resolve` keeps a workspace path it cannot inspect rather than falling back to `examples/data`. `questions.json` is the exception: `lint_path` reports an unreadable or non-UTF-8 file as a JL000 finding. The policy and fit loaders read through `contracts/_validation.read_json_file`, which names the file for invalid JSON, invalid UTF-8 and `NaN`/`Infinity`. Never wrap a computation in it: computations get pre-loaded records and run unwrapped so a server bug stays a 500; an input condition only detectable inside a computation gets its own exception type (`CompareInputError` in `eval/compare.py`) caught explicitly. Undefined judge kappa is `None` in `Agreement.as_dict()` (NaN is not valid JSON) and renders as "N/A". A missing optional file is still a 200 with empty data, and `/api/overview` lists it in `missing_files`. In `index.html`, every server-derived string passes through `esc()` before `innerHTML`; a test scans the template literals for unescaped identifier fields (an interpolation in a `.textContent =` statement is exempt), and `tests/test_web_harness.py` runs every view's loader, and its error path, over hostile API responses. The page is one inline `<script>` of top-level `function` declarations (four-space indent, closing line exactly `    }`), which the node tests load whole. Charts and tables go through the page's kits (`svgFrame`/`svgAxes`/`svgDots`/... build SVG as escaped text with CSS-token colors, the series tokens `--series-1`/`--series-2` being the dataviz skill's categorical slots, never a status color; `tableHtml` / `sortRows` / `filterRows` / `toCsv` / `toJsonRows`, with each table's sort and filter in the shell's `TSTATE`, re-rendering only that table's body); `/api/audit`'s `display.reliability_ci` is for the page only (`s1 audit` has no `display`). Its view state is one snapshot in the URL hash (`parseHash` / `formatHash`); a group view (`viewDefs()[v].group`) never requests while a chosen group is unresolved (`resolveGroup` / `groupReady`), so it cannot fall back to another group, and only `pickGroup` changes the group and the views' questions together.

**Routing.** `runtime/routing.py::route` is the only decision rule for a `PolicyEntry`: `DecisionGate` (`evaluate_noul` / `evaluate_choice` / `evaluate_score`), drift's escalation rate and both exporters' `policy_action` call it. The policy also chooses the distribution: calibrated exactly when `policy.calibrated`. The gate calibrates a live answer with its fit; reports go through `routing.route_record` / `policy_distribution`, which re-parse the record and take its stored `calib`, refusing (`RoutingInputError`, with the drift side) a calibrated policy for a record without one. Drift looks the policy up by the record's group key; its PSI/JSD/quantiles/entropy are a separate choice, raw unless `--calibrated` (`use_calib`), which refuses (`DriftInputError`) any answered record without `calib` rather than mixing distributions, and a group whose records on both sides name more than one `calib.fit_sha256` (null counts as one value, as in `tune`), since a refit would show as drift. It dispatches on `policy.primitive`, never on `classes` (`(0, 1) == (False, True)`). Choice/score: `error_budget` only, and a tie at the top or `threshold: null` escalates. For every primitive the gate refuses a calibrated policy without its fit, rather than route the raw distribution against a threshold tuned on calibrated values. Distributions are renormalized with `records.probability_total` (`math.fsum`) in the parser and the gate, so a tuned threshold compares bit-identically at runtime on every Python (plain `sum` is order-dependent on 3.11). Exports of policy-routed records carry `routing_rule` (`ROUTING_RULE`); bump it when the rule's outputs change.
